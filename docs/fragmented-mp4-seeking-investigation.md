# Fragmented MP4 Seeking Investigation

## Problem
In the Portal Android app, playing fragmented MP4 (fMP4) videos works correctly using Jetpack Compose and AndroidX Media3 1.11.1. However, seeking functionality—such as skipping backward by 5 seconds, skipping forward by 10 seconds, and dragging the progress slider—does not work.

## Investigation & Evidence
- **Media3 Extractor Configuration**: Fragmented MP4 files, especially those generated by Android `MediaMuxer` or `FragmentedMp4Muxer`, often have malformed `tfdt` box timestamps or lack `sidx` boxes. Media3 1.11.0+ introduced flags to support seeking in such files using the `mfra` box.
- **ExoPlayer Setup**: In `SpecificViewers.kt`, `ExoPlayer` is built using standard defaults `ExoPlayer.Builder(context).build()`. It does not configure a custom `ExtractorsFactory` with the required flags to enable fMP4 seeking.
- **Skip Durations**: The requirement states skipping backward by 5s and forward by 10s. The default ExoPlayer seek increments might differ. We need to explicitly set these using `.setSeekBackIncrementMs(5000)` and `.setSeekForwardIncrementMs(10000)`.
- **Compose UI**: The `CenterControls` component in `SpecificViewers.kt` passes empty lambdas for `backSecondary` and `forwardSecondary`. In Media3 Compose UI, the `backSecondary` and `forwardSecondary` slots correspond to the "Previous" and "Next" buttons in the single-item viewer, whereas the inner controls (`back` and `forward`) handle seek-back and seek-forward. The empty lambdas were correctly placed to hide previous/next.

## Root Cause
1. **Missing Extractor Flags**: Media3's default extractor for MP4 does not handle seeking in fMP4 without specific flags (`FLAG_READ_MFRA_FOR_SEEK_MAP`, `FLAG_WORKAROUND_IGNORE_TFDT_BOX`, `FLAG_ENABLE_EMSG_TRACK`). These flags provide seeking capabilities specifically for files with an mfra box or EMSG track. Indexless fMP4 files (lacking both sidx and mfra) require alternative seek strategies, such as providing a separate seek index or generating an index during file creation.
2. **Incorrect UI Configuration**: The `backSecondary` and `forwardSecondary` slots correspond to "Previous" and "Next", which should be hidden by empty lambdas, but were previously assumed to hide seek buttons.
3. **Missing Seek Increments**: The skip durations are not explicitly configured to 5s and 10s.

## Proposed Fix (Implemented & Verified)
1. Created a `DefaultExtractorsFactory` configured with the necessary flags:
   - `FragmentedMp4Extractor.FLAG_READ_MFRA_FOR_SEEK_MAP`
      - `FragmentedMp4Extractor.FLAG_WORKAROUND_IGNORE_TFDT_BOX`
   - `FragmentedMp4Extractor.FLAG_ENABLE_EMSG_TRACK`
2. Applied this factory to `ExoPlayer.Builder` using `DefaultMediaSourceFactory`.
3. Set `.setSeekBackIncrementMs(5000)` and `.setSeekForwardIncrementMs(10000)` on the `ExoPlayer.Builder`.
4. Maintained empty lambdas for `backSecondary` and `forwardSecondary` in `CenterControls` to properly hide the "Previous" and "Next" buttons while preserving the inner seek buttons.
5. These fixes were applied to both `VideoViewer` and `AudioViewer` in `04_portal/app/src/main/kotlin/rajnishkmehta/sakshi/portal/ui/viewer/SpecificViewers.kt`.
