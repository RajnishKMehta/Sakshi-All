# Constants & Specifications

This page outlines core ecosystem constants, limits, and behavior specifications implemented across Sākṣī components.

## General Application Constraints

*   **Minimum SDK:** All Sākṣī applications (SDK, Vault, Camera, Portal) enforce a strict `minSdk` of 29 (Android 10).
*   **Networking:** Applications operate strictly locally offline. No internet permissions are requested or used.

## Validation & Formatting

### File ID Constraints
Generated IDs (`fileId`) passed between apps via the SDK must strictly conform to:
*   **Characters:** Lowercase alphanumeric (`a-z`, `0-9`), underscores (`_`), and hyphens (`-`).
*   **Length:** 8 to 128 characters.
*   **Uniqueness:** Duplicate file IDs in copy or sync requests are strictly rejected by the Vault. They are not overwritten.

### Date Formats
*   AsciiDoc (`.adoc`) internal documentation dates follow `YYYY-MM-DD` standard.

## Architecture Specifications

### Storage & Security
*   **Location:** Vault stores finalized media in app-private internal storage (`Context.filesDir`).
*   **Encryption:** Media is stored unencrypted at rest, relying exclusively on Android OS sandboxing and file-level permissions to prevent unauthorized access.

### Crash-Safe Synchronization
When performing AV sync via Media3 `FragmentedMp4Muxer`:
*   Media3 1.11.0+ handles fMP4 seeking without `sidx` boxes using `mfra` boxes.
*   *Warning:* When extracting fMP4 generated by the native Android `MediaMuxer`, `FragmentedMp4Extractor.FLAG_WORKAROUND_IGNORE_TFDT_BOX` is used to bypass malformed boxes. However, this flag **must not** be used for fMP4 files generated by Media3's `FragmentedMp4Muxer`. Doing so breaks seeking by disrupting base decode time calculations.

### Clock Management & Deletion
*   Vault handles device time tampering mitigation during deletion workflows.
*   It utilizes the monotonic clock (`elapsedRealtimeMillis`) while the device `bootCount` matches the schedule time. It only falls back to the wall clock (`wallTimeMillis`) after a device reboot.

## UI / UX Standards
*   **Resource Naming:** Standard icon drawables follow the `ic_` prefix convention.
*   **Pull to Refresh:** When implementing pull-to-refresh on empty states in Compose, use a `LazyColumn` with `.fillMaxSize()` rather than a `Box` with `.verticalScroll()` to properly maintain vertical centering constraints.
*   **Navigation:** Portal uses `androidx.navigation3`. ViewModels are correctly scoped to navigation entries via `rememberViewModelStoreNavEntryDecorator()`. Avoid manually keying ViewModels when using this decorator.
