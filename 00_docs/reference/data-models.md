# SDK Data Models

The Sākṣī SDK utilizes strongly-typed data models for arguments and return types. These models encapsulate the required data, ensuring safe transmission across the IPC boundary between the client app and the Vault.

## Core Models

### `SakshiResult<T>`

The wrapper class for all asynchronous operations. It represents either the successful outcome or the failure of a request.
*   **`SakshiResult.Success(val data: T)`**: The operation succeeded, containing the result data.
*   **`SakshiResult.Failure(val error: SakshiError)`**: The operation failed, containing a typed error.

### `SakshiError`

The sealed hierarchy of explicit errors returned within a `SakshiResult.Failure`. See the [Error Handling](error-handling.md) documentation for details on each subclass.

## Request Models

### `FileCopyRequest`

Used by `copyFile` to request the ingestion of a single, complete file.

*   `fileId` (String): A unique identifier generated by the client application.
*   `uri` (String): The Content Provider URI of the source file.
*   `mediaType` (String): The category of the media (e.g., `"PHOTO"`, `"VIDEO"`, `"AUDIO"`, `"OTHER"`).
*   `fileExtension` (String): The extension representing the file format (e.g., `"jpg"`, `"mp4"`).
*   `timestamp` (Long): The epoch timestamp of the capture event in milliseconds.
*   `metadata` (Map<String, String>): Optional key-value pairs for additional information.

### `AVSyncRequest`

Used by `startAVSync` to initiate incremental, real-time synchronization for an active recording.

*   `fileId` (String): A unique identifier generated by the client application.
*   `uri` (String): The Content Provider URI of the actively recording file.
*   `mediaType` (String): The category of the media (e.g., `"VIDEO"`, `"AUDIO"`).
*   `fileExtension` (String): The extension representing the file format (e.g., `"mp4"`).
*   `timestamp` (Long): The epoch timestamp of when recording started in milliseconds.
*   `metadata` (Map<String, String>): Optional key-value pairs for additional information.

## Response Models

### `CopyDoneAck`

Returned upon the successful completion of a `copyFile` operation, or the finalization of a `stopAVSync` request.

*   `fileId` (String): The unique identifier.
*   `originalUri` (Uri?): The original source URI provided by the client, if applicable.
*   `totalCopiedBytes` (Long): The total number of bytes ingested into the Vault.
*   `timestampEpochMs` (Long): The epoch timestamp of completion in milliseconds.

### `AVSyncStatus`

Emitted periodically as a flow by `startAVSync` to represent the real-time progress of a recording synchronization.

*   `fileId` (String): The unique identifier.
*   `state` (AVSyncStatus.State): An enum representing the current synchronization state:
    *   `INITIALIZING`, `SYNCING`, `IDLE_WAITING`, `PAUSED`, `STOPPED`, `COMPLETED`, `FAILED`, `DELETE`.
*   `offsetBytes` (Long): The number of bytes successfully copied so far.
*   `totalBytes` (Long): The total size of the file, or `-1` if the recording is still ongoing.
*   `isCompleted` (Boolean): True if the synchronization process is finalized.
*   `message` (String?): Optional informational or error message.

### `RecordingQueryResponse`

Returned by `isAVSynced` to detail the Vault's current understanding of a specific file.

*   `exists` (Boolean): True if the file exists in the Vault database.
*   `syncState` (String?): The string representation of the `AVSyncStatus.State`, if it exists.
*   `offsetBytes` (Long): The last recorded byte offset copied.
*   `isCompleted` (Boolean): True if the recording is marked as fully copied.

### `MediaDetailsResponse`

Returned by `getMedia` to provide access details for a stored file.

*   `fileId` (String): The unique identifier.
*   `contentUri` (String): The Content Provider URI generated by the Vault, used to read the file data.
*   `mediaType` (String): The category of the media.
*   `fileExtension` (String): The file format extension.
*   `createdTime` (Long): The epoch timestamp of capture.
*   `sizeBytes` (Long): The file size in bytes.

### `VaultPingResponse`

Returned by `pingVault` to confirm the health and version of the Vault service.

*   `isAvailable` (Boolean): True if the service is active and responsive.
*   `vaultVersion` (String): The version string of the Vault app.
*   `timestamp` (Long): The current system time reported by the Vault.

## Batch Operation Responses

These models report the outcome of batch operations where some items may succeed while others fail.

### `BatchMediaDeleteResponse`

Returned by the batch `deleteMedia` overload.
*   `successfulIds` (List<String>): IDs of files successfully scheduled for deletion.
*   `failedIds` (Map<String, String>): A map where keys are IDs that failed, and values are the error messages.

### `BatchMediaRecoverResponse`

Returned by the batch `recoverMedia` overload.
*   `successfulIds` (List<String>): IDs of files successfully recovered.
*   `failedIds` (Map<String, String>): A map where keys are IDs that failed, and values are the error messages.
