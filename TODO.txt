## Goal

Currently, clicking a Photo, Video, Audio, or Other item in the Portal gallery does nothing.

Implement media opening/viewing for all four media types.

When the user clicks a gallery item:

1. Use the existing SDK `getMedia(mediaType, fileId)` API.
2. Obtain the Vault-provided content URI.
3. Use that URI according to the media type.
4. Do not access Vault's private filesystem or database directly.
5. Do not create another Vault API for this task.
6. Follow the SDK API usage documented in `01_sdk/docs/api_usage.adoc`.

Do NOT implement export yet.

The Download/Export button should only be displayed as a TODO UI element and must not perform any export operation yet.

# Video metadata

Video metadata must be handled separately from descriptive metadata.

Use:

`androidx.media3:media3-inspector:1.11.1`

and Media3's `MetadataRetriever` / relevant Media3 metadata APIs.

Before implementation, read the current official Google/AndroidX Media3 documentation for the exact API and current recommended usage.

Retrieve the actual video metadata/format information from Media3 `Format`.

Useful technical fields include:

- width
- height
- decodedWidth
- decodedHeight
- frameRate
- rotationDegrees
- pixelWidthHeightRatio
- sampleMimeType
- containerMimeType
- codecs
- bitrate
- averageBitrate
- peakBitrate
- colorInfo

Do not blindly assume every field is always available.

Only display values that are actually present/known.

Keep video metadata organized and readable.

Do not mix technical media information with descriptive metadata.

For example:

Descriptive metadata:
- Title
- Description
- Date
- etc.

Technical media information:
- Resolution
- Frame rate
- Codec
- Bitrate
- MIME type
- Rotation
- Pixel aspect ratio
- Color information
- etc.

The Info sheet should load video metadata only after the user opens Info.

Use the same Portal loading indicator while metadata is being retrieved.

When an Audio item is clicked:

1. Call `getMedia(mediaType, fileId)`.
2. Use the returned content URI.
3. Create/use a Media3 ExoPlayer instance.
4. Use Media3 playback controls.
5. Display the audio information and playback UI according to the Portal design.

## Audio descriptive metadata

Use Media3's metadata facilities.

Media3 exposes metadata through `MediaMetadata`.

Relevant fields include:

- title
- artist
- album title
- album artist
- composer
- genre
- track number
- disc number
- artwork

Read the official Media3 documentation first and use the current recommended API.

For playback metadata, use the Media3 player metadata APIs such as:

`player.mediaMetadata`

and/or:

`onMediaMetadataChanged(MediaMetadata)`

as appropriate.

Do not assume that every audio file contains every field.

Only display metadata that actually exists.

## Album artwork

If the audio contains album artwork:

- Display the artwork prominently in the audio viewer.
- When audio is paused, show the album artwork as the main visual.
- If no artwork exists, use the Portal's fallback audio visual.

# Audio playback animation

For the audio visualization, do NOT add a heavyweight audio visualization/equalizer library.

Use:

- Jetpack Compose `Canvas`
- `rememberInfiniteTransition`
- Media3 `Player.isPlaying`

Create lightweight decorative animated bars.

Important behavior:

- When the player is playing:
  - Animate the decorative bars.
- When the player is paused:
  - Stop the animation.
- If album artwork exists:
  - Show the album artwork while paused.
  - During playback, show the decorative animated visualization appropriately.
- If album artwork does NOT exist:
  - Keep the decorative bars/visualization visible even while paused.
  - When paused, the bars remain visible but stop moving.
- The bars must not look like a completely separate visual system.
- Use the current Portal Material 3 / Material You theme colors so the visualization naturally matches the current theme.
- Do not hard-code an unrelated color palette.

Keep the animation lightweight and efficient.

Do not continuously run an animation when the player is paused.
